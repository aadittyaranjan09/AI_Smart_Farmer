Project Documentation

AI Smart Farmer

AI Smart Farmer is a full-stack agriculture web application that combines weather intelligence, crop recommendation, user authentication, profile management, and dashboard-style farm insights in one place.

This project is built as a modern Node.js and Express application with a static frontend, JSON fallback storage, optional MongoDB persistence, and protected user flows for login, profile updates, and prediction history.

Node.js Express MongoDB Optional JWT Auth HTML / CSS / JavaScript Weather APIs
Purpose

Help farmers and agriculture users make faster decisions with weather data, crop suggestions, and a guided dashboard experience.

Current Scope

The app already supports authentication, live weather lookup, geolocation usage, crop prediction, local history, and profile management.

Deployment Ready

The codebase includes a Render configuration and can run with MongoDB or fallback local JSON data files when the database is unavailable.

Core Features

  • User registration and login with email and password.
  • Google sign-in flow support from the frontend integration.
  • JWT-based protected routes for profile and session validation.
  • Live weather search by city or by browser geolocation coordinates.
  • Automatic fallback to Open-Meteo when the OpenWeather API key is rejected.
  • Weather alerts for rain, thunderstorm, high wind, and heat stress conditions.
  • Simple crop recommendation logic based on temperature and humidity.
  • Prediction history tracking with MongoDB or JSON storage fallback.
  • Profile update support with theme and locale preferences.
  • Dashboard widgets for soil tips, mock disease analysis, and farm analytics.

How the App Works

Frontend Flow

Users sign in, open the dashboard, fetch weather by city or location, generate crop recommendations, review prediction history, and manage their profile from dedicated pages under the public folder.

Backend Flow

Express serves static files, exposes authentication and farming APIs, validates sessions with JWT, and stores user or prediction data in MongoDB when available, or local JSON files otherwise.

Technology Stack

  • Frontend: HTML5, CSS3, vanilla JavaScript, Chart.js, Leaflet.
  • Backend: Node.js, Express 5.
  • Authentication: JWT, bcryptjs, frontend Google sign-in integration.
  • Database: MongoDB with Mongoose.
  • Fallback storage: local JSON files in data/users.json and data/predictions.json.
  • External services: OpenWeather API and Open-Meteo geocoding/forecast fallback.

Important API Endpoints

Authentication
  • POST /api/auth/register - Create a new user account.
  • POST /api/auth/login - Sign in with email and password.
  • POST /api/auth/google - Sign in or create account with Google details.
  • GET /api/auth/me - Fetch the currently authenticated user.
  • PUT /api/auth/profile - Update profile, avatar, theme, and locale.
Farm Intelligence
  • GET /api/weather - Fetch current weather and forecast by city or coordinates.
  • POST /api/predict - Generate a crop recommendation.
  • GET /api/history - Read recent crop prediction history.
  • GET /api/health - Check API and storage health.
  • GET /health - Basic server health response.

Environment Variables

  • PORT - Server port. Defaults to 5000.
  • JWT_SECRET - Required for authentication token signing.
  • MONGO_URI - Optional MongoDB connection string.
  • OPENWEATHER_API_KEY - Required for the primary weather provider.

If MONGO_URI is missing or the connection fails, the app continues with local JSON storage. If the weather key fails with an authorization error, the backend falls back to Open-Meteo for live weather data.

Run the Project

  1. Install dependencies with npm install.
  2. Create a .env file and add the required keys.
  3. Start the server with npm run dev for development or npm start for production.
  4. Open the app in your browser through the running Express server.
PORT=5000
JWT_SECRET=your-secret-key
MONGO_URI=your-mongodb-uri
OPENWEATHER_API_KEY=your-openweather-key

Current Limitations and Future Improvements

  • The crop recommendation engine currently uses simple rule-based logic instead of a trained ML model.
  • Disease detection is a mock UI flow and does not yet call a real image classification service.
  • Analytics data is currently static and can be replaced with real farm performance metrics.
  • Localization preferences exist, but multilingual UI implementation is still pending.
  • An AI chatbot, subscription plans, and admin tools are planned areas for expansion.

AI Smart Farmer is a practical smart agriculture dashboard project that already demonstrates strong full-stack structure: secure authentication, external API usage, fallback resilience, dashboard UX, and deployment readiness.
